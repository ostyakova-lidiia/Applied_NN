## Финальный проект

Финальный проект можно выполнять **индивидуально** или **в парах**. Если проект выполняется двумя студентами, ожидаемый объём работы должен быть больше: например, более сложная постановка задачи, больший объём данных, более подробное сравнение методов, расширенная экспериментальная часть или более проработанная реализация. Проект не обязан быть идеальным или промышленно готовым. Главное — показать, что вы умеете поставить задачу, выбрать подходящие методы, реализовать рабочий прототип или эксперимент, проанализировать результат и объяснить свои решения.

Проект должен охватывать **как минимум две темы**, изученные в рамках курса.

### Формат сдачи

Проект должен быть оформлен в виде репозитория на GitHub.

В репозитории должны быть:

- код проекта в формате `.ipynb` или в виде отдельных `.py`-файлов;
- файл `README.md` с описанием проекта;
- инструкция по запуску;
- описание данных, если они используются;
- краткое описание методов;
- результаты и выводы.

Будтье готовы объяснить любой фрагмент своего кода и ответить на вопросы по выбранным темам.

### Критерии оценивания

Максимальная оценка за проект — **10 баллов**.

1. Код — 3 балла

Оценивается качество реализации проекта.

**Критерии:**

- код запускается и соответствует заявленной задаче;
- структура проекта понятна;
- репозиторий аккуратно оформлен;
- есть `README.md` с описанием проекта и инструкцией по запуску;
- студент может объяснить, что делает каждый ключевой фрагмент кода.

2. Идея проекта — 2 балла

Оценивается постановка задачи и обоснованность выбранного подхода.

**Критерии:**

- задача сформулирована ясно;
- идея проекта доведена до логического завершения;
- выбранные методы подходят для решения задачи;
- проект охватывает как минимум две темы курса.

 3. Защита проекта — 3 балла

Оценивается качество устной презентации проекта и его демонстрация. 

Защита должна включать:

- обоснование выбора темы;
- краткий обзор проблемы, задачи или технологии;
- описание использованных данных;
- описание методов и архитектуры решения;
- представление результатов;
- анализ ошибок или ограничений;
- возможные направления развития проекта.

Защита проекта должна включать демонстрацию результатов работы (например, работу системы RAG, сравнение дообученной модели и бейзлайн модели на отдельных примерах).

4. Вопросы по выбранным темам — 2 балла

На защите студентам будут заданы **два вопроса** по темам курса, которые использовались в проекте.

Например, если проект объединяет RAG и fine-tuning, вопросы могут быть связаны с retrieval, embeddings, chunking, генерацией ответа, переобучением, evaluation или особенностями fine-tuning.

**Критерии:**

- студент понимает основные понятия выбранных тем;
- может объяснить, почему использовал конкретный метод;
- понимает ограничения выбранного подхода;
- может связать теоретические понятия с реализацией своего проекта.
